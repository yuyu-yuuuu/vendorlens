# 首轮修复与固定集复测

已针对基线误判修复规则和工具控制流程。这是看过失败样例后的开发集复测，不是独立测试，不证明生产泛化。原始标签、检索语料和12条模型输入均未修改，数据与输入SHA-256与基线一致。真实模型输出本身有随机性，单次前后对比不能证明全部差异都由代码引起。

## 修改

- 成本工具核验失败后，不再强制下一轮重复调用 calculate_tco；允许检查有来源的费用或返回其他领域并标记成本失败。达到工具轮次上限后请求最终输出，模型继续调用工具仍报错。未放宽金额门禁或增加轮次上限。
- 区分采购要求、待确认及未回答材料与供应商能力；补充不可用、版本否定、未来能力、数值上限及限制条件识别。仍为词法规则，不具有通用语义理解能力。

## 同集结果

| 指标 | 基线 | 修复后 |
| --- | ---: | ---: |
| 离线规则判断 | 11/32（34.38%） | 24/32（75.00%） |
| 离线规则 Macro-F1 | 0.2964 | 0.7262 |
| 模型集成可交付的需求判断正确数 | 2/12 | 12/12 |
| executor 整条输入抛异常 | 7/12 | 0/12 |
| 三个领域均 completed | 5/12 | 5/12 |
| 模型集成中确定 TCO 正确数 | 4/10 | 6/10 |
| 离线确定 TCO 正确数 | 6/10 | 6/10 |
| Hybrid Recall@3 | 77.50% | 77.50% |

需求判断12/12只是这12条已知开发样例，不能当作泛化准确率。其他领域仍然会失败；三个领域均返回只有5/12，整体评审质量没有达到满分。未知TCO的两条模型输入中，一条正确未输出TCO，一条仍将50000元实施小计作为完整TCO。

完整后端回归 240 项通过，XML见 [pytest.xml](repair-1/pytest.xml)。模型复测记录保存于 [metrics.json](repair-1/metrics.json)、[固定输入](repair-1/model-inputs.json)及[实际模型输出](repair-1/real-model-progress.json)。本轮运行结束时数据和业务代码哈希校验通过，随后仅调整了一处反馈文字长度以通过lint。

## 尚未解决

- 同义改写、对别的能力的否定、并发数量约束仍可能误判；规则失败样例见下表。
- 单价数量、税率、季度、折扣和费用缺项仍未完整处理。
- 部分承诺或成本领域仍被输出校验拒绝。控制流程允许其他领域交付，但不能把领域失败当成评审成功。
- 需要独立标注且未参与修复的实际文档集，以及重复模型运行，才能评估泛化与稳定性。
