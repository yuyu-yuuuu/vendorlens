# 父块上下文与子块引用

## 这次解决的问题

此前数据库已经回查父块，但 coordinator 转换 EvidenceItem 时只保留 matched_child.text，父块全文在转换边界丢失。模型最终只看到子块，因此可能忽略同一段落后面的限制条件。

例如父块包含“支持私有化部署”，后面又写“仅限企业版，需额外购买授权”。子块帮助检索定位前一句，父块帮助模型理解完整承诺。这次没有增加 Agent，也没有修改金额门禁。

## 字段各自负责什么

| 字段 | 含义 |
| --- | --- |
| context_text | 完整父块原文，理解上下文 |
| quote | 命中子块的连续原文，精确展示引用 |
| chunk_id | 父块 ID |
| matched_chunk_id | 命中的召回块 ID；表格独立行可等于父块 ID |
| source_text_hash | 父块全文 UTF-8 字节的 SHA-256，不是子块哈希或文件哈希 |
| document_version_id | 本次冻结的文档版本 |
| location | 父块的页码、段落、行号或单元格定位，不是子块字符偏移 |

## 按代码顺序学习

1. `parsers.py`：切片仍按句子累积并限制到 320 字符，但保留句间空格与换行，避免拼接后的 quote 在父块中不存在。这里只对最终子块两端去空白。
2. `coordinator.py` 的 `_to_evidence`：parent.text → context_text；matched_child.text → quote。父子内容不再相互替代。
3. `schemas.py` 的 `EvidenceItem.validate_parent_context`：全文存在时，检查 SHA-256 与 source_text_hash 一致，再检查 quote in context_text。哈希不一致或引用不属于该全文，构造输入即失败。
4. `model_analyzer.py` 的 `_messages`：model_dump 将新字段放进用户输入，系统提示明确区分父块上下文与子块引用，并要求说明引用外的限制条件；资料中的指令不能覆盖系统规则。

## 验证与边界

测试覆盖长段落摄取、真实本地索引/父块回查、评审输入和模型消息序列化；限制条件与承诺不在同一子块中时，模型消息仍有完整父块。也覆盖哈希错配、伪造引用、空白保留、独立行、旧字段序列化兼容。

模型消息测试不调用付费模型，只证明上下文实际进入请求，不证明模型每次都理解正确。确定性抽取/比对工具仍只读取 quote，因此工具判断可能缺少父块限定条件；旧任务快照也不会自动回填。更长父块会增加模型输入 Token，目前没有新加截断策略，以免再次丢失限制条件。哈希与包含校验只证明输入内部一致，不能独立证明其来自可信文件。

旧数据库中已经生成的子块不会因修改解析器自动变化。如果旧切片删除了句间空白，导致子块不是父块的连续原文，新校验会拒绝它；需要重新解析并重建这些子块及索引，单独重写索引或重复上传相同文件不会修复（幂等上传会复用旧版本）。本次没有自动重建已有数据。
