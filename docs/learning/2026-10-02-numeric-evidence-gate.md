# 数字事实与成本证据门禁

## 业务目的：计算正确还需要输入有依据

以前引用 `cost-ev` 就能向 calculate_tco 填入 80 万实施费、10 万年费和 5 万可选费，即使该证据只写了实施费用 80 万。工具算出 110 万的算术没有错，事实却没有依据。

旧 evidence.py 有 Claim 级数字匹配，但正式执行返回 VendorAssessment，没有经过旧 Claim gate。旧数字集合也不足以区分 30 天、30%、30 元。此次补全的是正式执行上的数字和来源约束，继续使用单个 VendorReviewAgent、三个领域和供应商间并行。

父块上下文的传递、哈希及包含校验来自之前未提交的改动，详见同目录的父块上下文学习记录。本次沿用该契约，没有重建历史子块。

## 实际数据流

```text
coordinator 从数据库读取冻结父块，构造 EvidenceItem
  → VendorReviewInput 校验冻结范围、证据 ID 唯一性与领域内容一致性
  → model_analyzer 向模型发送父块、子块引用、配置、返工原因
  → 可用 extract_cost_items 查看所引原文费用来源
  → calculate_tco 自行提取费用，比较模型输入与原文分类合计，再计算 TCO
  → 权威费用与来源覆盖模型成本字段，保留缺失信息
  → VendorReviewExecutor 校验身份/范围，再逐领域核验数字
  → workflow.validate_domains 再检查，失败领域局部返工
  → 两次返工后，同规则成本降级并在出口复检
  → 只有通过或明确降级的载荷进入评分和报告
```

旧快照 context_text=None 时只用 quote；有父块时允许数字出现在 quote 外的父块句子里，但仍绑定实际引用的 evidence_id，不改写 quote。CostSourceItem 的字符区间相对于实际使用的 context_text 或旧 quote，source_text 是该区间的连续原文。location 仍来自父块。业务结果本身按现有 JSON 结果存储，不需要数据库迁移。

## 重点代码

- `numeric_facts.py`：NumericFact 不再只是一个 Decimal，而是“类型、值、单位、金额周期”。金额按万/亿归一化，完整日期按真实日历验证，百分比保留 %，百分点独立，年/月转为月，日/小时转为秒，工作日与人天不借用自然日换算。常见中文整数先转换；这是有限格式规则，不能理解所有自然语言数量表达。
- `cost_grounding.py`：费用按独立片段提取；月费乘 12 得年化持续费。按版本、父块和片段区间去重，避免多个子块命中同一父块后重复计费。不同区间即使金额相同也不合并。GroundedCosts 用 Decimal 累加；网络输出保留现有 float Schema。
- `schemas.py`：CostSourceItem 保存金额与连续原文的联系；CostAssessment.cost_sources 默认空列表兼容旧结果；成本字段拒绝 NaN/Infinity。
- `review_tools.py`：calculate_tco 先校验原文分类合计，再保存 authoritative_cost。normalize_cost 只是算术辅助，不能绕过来源门禁。失败的后一次计算清除旧权威结果，防止沿用过期授权。
- `model_analyzer.py`：成本来源错误作为工具响应送回模型，可在工具循环内纠正。最终没有成功的权威工具结果时只清空成本领域；有权威结果时覆盖数值和本地来源，但合并保留模型与规则发现的缺失项。
- `evidence.py`：validate_numeric_output 核验每条需求和承诺自己的引用，不使用供应商全部资料的数字集合。付款条款使用成本引用；摘要使用领域内引用并集。成本合计与 TCO 再验证，来源区间重新构造。错误生成 failed DomainAssessment，不携带可评分的错误成本或承诺。
- `review_agent.py`：正式执行调用门禁，并重验证 model_copy/嵌套可变对象形成的输入。领域证据必须与总输入中同 ID 的证据完全一致，不能用同 ID 偷换文本。
- `workflow.py`：验证节点和降级出口调用同一门禁；revision_feedback 把失败码送入下一次同 Agent 调用，已成功领域保留。
- `fallbacks.py`：成本降级使用同一个 GroundedCosts，不再把所有金额粗略相加，也不把月费当一次性或把 CNY 标成 USD。

## 一个完整的小例子

原文：`实施费用80万元，月费1,000元，可选培训5万元。`，冻结比较周期 18 个月。

| 来源片段 | 原金额 | 归类 | 年化金额 |
| --- | ---: | --- | ---: |
| 实施费用80万元 | 800000 CNY | one_time | 800000 |
| 月费1,000元 | 1000 CNY | recurring/monthly | 12000 |
| 可选培训5万元 | 50000 CNY | optional/one_time | 50000 |

模型必须提交一次性 800000、年化持续 12000、可选 50000。工具计算 `800000 + 12000 × 18 / 12 = 818000`。818000 无须出现在原文中，它的依据是费用片段和冻结配置。可选费用单独展示，不进入基础 TCO。

成本结构中的 TCO 始终复算。成本摘要明确写“TCO/总拥有成本”时可使用这个派生金额与 18 个月比较口径；付款条款“首付818000元”仍必须有原文，不能因为金额恰好等于 TCO 就通过。

## 失败示例与测试

| 输入/输出问题 | 处理 |
| --- | --- |
| 原文 80 万，提交 90 万 | cost_input_mismatch:one_time |
| 原文月费 1000，提交年费 1000 | cost_input_mismatch:recurring；正确年化为 12000 |
| 原文 90 天，输出 90 个月/90 工作日 | numeric_fact_mismatch:commitment[...] |
| 原文 30%，输出 30 个百分点 | 维度不匹配 |
| 原文 CNY 100，输出 USD 100 | 币种不匹配，不换汇 |
| 输出日期不存在或与原文日期不同 | 日期不匹配 |
| 需求只引部署证据，却写支持 90 人 | 不允许借承诺证据中的 90 |
| 成本数值正确，付款条款凭空写首付 30% | 成本领域失败 |
| 正确工具结果后又尝试错误金额 | 清除旧权威结果，须重新成功计算 |
| 同父块多个证据命中同一费用 | 同一来源区间只计一次 |
| 降级处理器返回凭空 TCO | 出口标记 failed，删除成本载荷 |

测试主要位于 test_numeric_facts、test_cost_grounding、test_review_tools、test_review_agent、test_model_analyzer、test_workflow 和 test_fallbacks。工作流回归走真实执行器，验证首轮加两次返工、只重做成本、失败原因进入提示、降级成本恢复为原文 80 万、其他领域返工次数保持零。所有模型测试使用 SequenceModel 或假 HTTP，不访问付费模型。

## 设计取舍与当前边界

本次选择“共同规则、保守拒绝含糊费用”。工具成功、模型出口和降级的规则一致，避免正常路径拒绝虚构金额而降级再次引入。使用来源片段与区间而非只保存全局 evidence_ids，也避免模型自行提供 provenance 就得到授权。

明确币种的独立报价可按一次性、月费、年费归类；未标周期的独立报价按一次性解释。季度/每日、单价乘数量、汇总与明细关系、估价、税费条件、多年打包、周期性可选费用等需进一步确认，不能猜算。常见数字叙述可以中文整数匹配，但成本提取当前仅接受阿拉伯数字金额。不读取跨块表头推断币种，不自动换汇。

没有可用费用项时成本失败；部分可用时只形成已知费用小计并保存 missing_costs，降级降低推荐等级。没有提取到某类别的零值不等于免费；必要费用类别是否齐全、是否遗漏另一份材料，需要后续完整性规则。

数字匹配只证明值和支持的维度在实际引用中存在，不能证明数字指向同一对象、合同起算条件相同、范围限定或否定语义正确。需求/承诺抽取工具仍主要读取 quote，不能声称所有确定性工具已具备父块语义理解。旧数据库切片与索引不自动重建。

旧 Claim gate 保留数据库来源校验，并复用新的维度匹配及 statement 核验；正式 VendorReview 执行使用新的领域门禁。正式输入信任 coordinator 从数据库组装的冻结包，内部哈希/包含校验不是独立的文件真实性认证。
