# 会话记忆、Skills 与模型路由

## 接入位置

```text
创建会话 → 保存讨论与显式偏好
创建评审任务
  → 最近消息 + 按项目/用户/版本过滤的历史摘要 + 长期偏好
  → 按行业与领域选择 Skill，保存版本、正文及内容哈希
  → 保存需求、参数、记忆和规则快照
Worker
  → 检索当前供应商与采购方材料，冻结版本
  → 再按实际版本过滤历史摘要
  → 每次供应商分析选择模型端点
  → 执行工具循环与原有证据/数字门禁
  → 将请求耗时、错误、领域失败比例和费用估算反馈到路由
  → 局部返工时重新选择端点
  → 报告、评审摘要与会话回复事务落库
```

## 三层记忆

`conversation_memory.py` 提供 `ConversationMemory`：

- 工作记忆读取数据库最近消息，默认最多 6 条、有效期 24 小时；可开启 Redis TTL 缓存。缓存与数据库结果比对，回滚或过期数据不会覆盖数据库。
- 未压缩消息到 16 条时，将较早消息压缩为最长约 3500 字的摘录摘要，保留最近 6 条。当前是确定性摘录，不调用 LLM 总结。
- 情景记忆存于数据库，评审结束后按供应商保存摘要、任务 ID、来源版本与 evidence_ids。消息压缩也保留关联评审的版本依赖。
- 历史摘要最多取最近 200 条候选，以本地 BM25 + 哈希向量混合检索排序。开启 Chroma 后建立 256 维哈希摘要向量，只检索数据库范围过滤后的 memory_id；不可用时回退本地排序。
- 用户偏好通过显式 PUT 保存，支持周期、币种、报告风格与关注维度；普通消息不自动修改偏好。周期/币种优先级为本次显式参数、项目配置、用户偏好、默认值。
- 记忆按 project_id、user_id、session_id 区分。用户 ID 是客户端提供的应用作用域，当前共享 Bearer Key 不是用户身份认证。

创建任务时记忆上下文进入 request_snapshot，随后进入 WorkflowState 和 VendorReviewInput.memory_context。输入包构建时按实际冻结版本再次过滤摘要，并排除其他供应商的评审情景。模型通过 conversation_context 读取背景，引用只能使用当前输入包的证据。

消息保存接口只记录讨论；需要评审结果时，使用同一 session_id 创建任务。任务完成后的摘要回写为 assistant 消息。当前没有独立的开放式逐字对话生成接口。

## Skills 热加载

`skills.py` 的 SkillManager 支持 JSON 文件和带 JSON front matter 的 SKILL.md：

```markdown
---
{"id":"software","version":"1.0","industries":["software"],"domains":["cost_modeling"]}
---
核验许可、实施和维护费用的币种、周期与缺失类别。
```

字段还包括 enabled 和 keywords；general 行业规范对所有行业生效。选择时按行业、领域、开关及可选关键词匹配，提交时保存正文和 SHA-256。模型提示词使用快照，返工时按领域选择其中的规范。

每次创建任务检测文件内容变化；POST /skills/reload 可显式重新加载。所有文件先整体校验，再用锁原子替换缓存。坏文件保留上一代有效规则，首次加载失败返回错误。规则目录在 API 与 Worker 容器共享只读挂载，新任务自动读到更新。

Skill 不注册工具；工具权限、成本计算、数字校验和推荐规则仍由代码执行。现有任务恢复继续使用快照，不读取新正文。

## 监控反馈路由

`model_routing.py` 为每次供应商 Agent 尝试选一个端点，整个工具循环保持同一端点。默认从已有 MODEL_* 配置产生 default 端点；配置 MODEL_ENDPOINTS 数组后可在多个支持工具调用的端点间选择。

routing_attempts 保存候选分、所选端点、状态、错误类型、模型请求耗时、失败领域比例和完整用量的单价估算。配置哈希由非密钥字段生成，数据库和 API 不保存 API Key 或原始异常文本。

最近 15 分钟最多取 200 个已结束样本，达到最少 3 个样本后计算健康分：

```text
基础分
  - 60 × 请求异常尝试比例
  - 20 × 限流尝试比例
  - 40 × 失败领域比例均值
  - min(P95 请求耗时 / 目标耗时 × 10, 30)
  - 费用惩罚
```

费用惩罚使用完整报告用量的尝试平均费用，最多 10 分，仅在端点使用同一币种时比较。这是启发式规则，实际效果需任务数据校准。领域失败包括结果缺失和证据门禁拒绝，不是独立人工质量评分。

异常尝试或失败领域比例达到 50% 时进入默认 60 秒冷却。冷却到期后允许一个探测尝试，数据库 compare-and-swap 领取默认 120 秒探测租约；其他调用选可用端点。健康探测清除冷却并将旧异常排除出当前评分窗口；失败探测重新冷却；探测中断后租约到期可重新领取。

所有端点都不可用时返回可分类错误，工作流在有限返工后走确定性降级。单端点没有替代端点时也遵守冷却，在冷却期内不会反复调用模型。路由记录通过 /routing/health、/tasks/{task_id}/routing 和 Trace 的 routing 跨度检查。
